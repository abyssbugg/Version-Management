yours to edit, and how changes reach your machine. See
[SECURITY.md](../docs/SECURITY.md) for the mutation gates behind the
"applied by" paths.

## The canonical theme: `professional-dev-p10k.zsh`

- **What it is:** the only theme `setup-theme.sh` can install
  (`DEFAULT_THEME="professional"`). It is generated by the PowerLevel10k
  configuration wizard (per its own header), extended with customization
  variables (`P10K_PROF_*` defaults via `: ${VAR:=value}`).
- **How it reaches your machine:** `setup-theme.sh` /
  `scripts/fix-terminal-issues.sh fix-p10k` replace `~/.p10k.zsh` with
  this file's contents under a backup transaction (hash-verified rollback,
  byte-compare idempotency).
- **Edit guidance:** do **not** hand-edit the installed `~/.p10k.zsh` —
  the next apply will overwrite it. Two sanctioned customization points:
  - Set `P10K_PROF_*` variables **before** the theme is sourced (for
    example in `~/.zshrc` before the p10k config loads).
  - Create `~/.p10k-professional-overrides.zsh`; the theme sources it
    automatically at load time (see the "Load user overrides" line in the
    file).
- To regenerate a completely different prompt, run `p10k configure` on
  your machine; note the result will diverge from this repo copy and the
  next suite apply will replace it (rollback is available).

## User overrides: `p10k-overrides.example.zsh`

This file is an **example** — never edit it in place and expect effects.

1. Copy it to your home directory: `cp config/p10k-overrides.example.zsh ~/.p10k-overrides.zsh`.
2. Edit the copy freely (it is yours; the suite never writes it).
3. Source it from `~/.zshrc` **after** the p10k config, per the
   instructions at the bottom of the example:

```zsh
[[ -f ~/.p10k.zsh ]] && source ~/.p10k.zsh
[[ -f ~/.p10k-overrides.zsh ]] && source ~/.p10k-overrides.zsh
```

Naming note (actual repo behavior): the professional theme auto-sources
`~/.p10k-professional-overrides.zsh` internally, while this example
documents the `~/.p10k-overrides.zsh` + manual-source-line mechanism.
Either works; the professional-override filename is the one picked up
without editing `~/.zshrc`.

## VS Code settings: `vscode-settings.template.json`

- **What it is:** a template, not a settings file. Every
  `{{PLACEHOLDER}}` token (`{{NVM_DIR}}`, `{{NODE_VERSION}}`, …) is
  substituted with real system values at generation time.
- **Generated, not applied directly.** Produce your settings with:

```bash
./scripts/generate-vscode-settings.sh
```

- **Edit guidance:** edit the **template** in this repository when you
  want a change for everyone; edit only the **generated output** on your
  machine for local, non-reproducible tweaks (it will be overwritten on
  the next generation). The generator and theme setup back up the
  existing VS Code user settings before writing (`create_vscode_backup`).

## Presets (`presets/` and the alternate `*-p10k.zsh` files)

Fragment/preset assets for hand-picking prompt elements. None of them is
installed by any script today. To use one: copy it, merge the desired
`POWERLEVEL9K_*` assignments into your override file (see the overrides
section above), and source as usual. If you add a new `.zsh` file here,
`make syntax-check` will verify it with `zsh -n`.
